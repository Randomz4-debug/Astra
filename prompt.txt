PRIVACY-FIRST REQUIREMENT

Astra must support a strict LOCAL-ONLY mode.

In Local-only mode:
- No cloud AI.
- No OpenAI requests.
- No analytics.
- No telemetry.
- No Firebase.
- No remote logging.
- No uploading microphone audio.
- No uploading camera frames.
- No uploading screenshots.
- No uploading notification/message content.
- No cloud storage.
- Keep supported processing on-device.
- Do not silently fall back to the Internet.

If technically feasible for the selected build variant, omit INTERNET permission from a Local-only build. Otherwise provide a build/configuration that has no network client and clearly shows network access disabled.

The application must never secretly record audio, secretly activate the camera, secretly capture the screen, or bypass Android security/privacy protections.

AI PROVIDER MODES

Implement:

1. LOCAL MODE
Everything possible happens on the phone:
Wake word -> local STT -> local command/intent engine -> local LLM when needed -> local vision/OCR -> local tool execution -> local TTS.

2. OPENAI / CHATGPT MODE
Optional and explicitly enabled by the user.
Use the current official OpenAI realtime API appropriate for live, full-duplex voice.
Do not copy/extract the ChatGPT Android app or proprietary assets.
Do not hard-code API keys into the APK.
Use secure session/ephemeral credential handling where appropriate.
Clearly tell the user that this mode requires Internet access.
Keep device-control tools local: the model requests a tool, Astra validates permission/confirmation, and Astra executes it.

3. AUTOMATIC MODE
Prefer local deterministic commands and local AI. Use OpenAI only when the user explicitly permits it and the feature requires it.
